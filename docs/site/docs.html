PROJECT DOCUMENTATION

Know what is ready — and what is not.

This is a public overview of the current repository. The source README, master specification, and project-state notes remain authoritative for exact implementation status.

Early preview · Phase 0. NetPulse is not ready for production monitoring. Authentication, persistent storage, real device monitoring, discovery, and alert delivery are not implemented. Docker/lab runtime integration and final UI review remain open gates.

Project status

The current repository contains an API foundation, a bilingual Next.js dashboard shell, CI and verification scripts, and an isolated network-lab contract. Empty dashboard values are intentional: the interface does not invent live readings.

Automated non-container checks have been recorded as passing in the repository state; this does not mean Docker, end-to-end UI, or release checks have passed.

Read the English README, README Bahasa Indonesia, and project state.

Architecture at a glance

  • Web UI: Next.js App Router, TypeScript, React, Tailwind CSS, and Storybook under frontend/.
  • API foundation: FastAPI and Uvicorn under backend/; readiness honestly remains unavailable until dependencies exist.
  • Runtime: Docker Compose with a separately opted-in lab overlay. Do not enable the lab on a network you do not control.
  • Quality gates: locked dependency installation, static checks, tests, frontend build, audits, secret scanning, and browser checks in GitHub Actions.

Feature detail and acceptance criteria live in the specification index.

Local development

Use Windows PowerShell, Git Bash, or WSL from the repository root. Check frontend/package.json, backend/pyproject.toml, lockfiles, and .env.example for the exact tool versions and settings before installing.

1. Prepare local environment settings

Copy-Item .env.example .env

Do not put tokens, router credentials, community strings, or passwords in Git. Keep the local .env untracked.

2. Run quick verification

./scripts/verify.ps1 -Mode quick

From Git Bash or WSL:

bash ./scripts/verify.sh --quick

3. Run full checks

./scripts/verify.ps1 -Mode full

Full verification installs locked dependencies, runs the repository static and test gates, builds the frontend and Storybook, and records a report. It deliberately does not count the deferred Compose smoke as passed.

4. Docker integration

The repository documents docker compose up --build for final integration, but the current project state still marks runtime validation as open. Do not assume the stack is production-ready until documented smoke checks pass.

Verification levels

  • Static and unit checks: automated in CI; results are linked from the repository Actions tab.
  • Build and Storybook: automated frontend checks. Browser screenshots, keyboard operation, and accessibility evidence need visual review.
  • Runtime integration: Docker Compose, readiness, isolated lab, and synthetic SNMP runtime checks must be explicitly run and recorded.
  • Release review: independent code/security review and an honest status report are required before making production claims.

See CI runs and the verification protocol.

Security boundaries

  • Use diagnostics and scanning only against localhost, isolated lab fixtures, or networks you own or are expressly permitted to test.
  • Keep Compose services bound to loopback unless the official security and deployment guidance is followed.
  • Never commit .env, database files, backups, router credentials, SNMP secrets, personal device inventories, or API tokens.
  • No production authentication exists yet. Do not expose the preview to an untrusted network or rely on it for real operations.

For vulnerability reporting, follow SECURITY.md. Contribution rules live in CONTRIBUTING.md.

Feature roadmap

Foundation — current

Repository conventions, API/web shells, CI, safe defaults, verification scripts, and static lab contracts.

Phase 1 — planned

Setup and authentication flows, device management, a working monitoring loop, status transitions, dashboard data, and alert basics.

Later phases — planned

Additional checks (TCP/HTTP/DNS/TLS), SNMP, discovery, incidents, topology, reports, integrations, status pages, and stronger operational tooling.

Roadmap entries are not a promise that every item is implemented. Scope changes should be reflected in the specification and traceability notes.
